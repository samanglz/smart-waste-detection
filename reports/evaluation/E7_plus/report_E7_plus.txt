E7 Plus: Real-World Domain Adaptation for Smart Waste Detection

======================================================================


E7 Plus is the final experiment of the Smart Waste Detection project. Its objective is to improve the real-world robustness of a YOLO11m detector through a modular synthetic data generation and domain adaptation pipeline while preserving a fair evaluation protocol.

Unlike previous experiments, E7 Plus does not modify the validation or test distributions. Only the training set is extended with generated samples.

The core methodology combines two complementary composition strategies:

1. Real-world background composition, which exposes waste objects to previously unseen environmental contexts and reduces the background domain gap.

2. Multi-object composition on existing training images, which increases scene complexity by introducing multiple waste instances, different classes, overlap, and partial occlusion.

These two strategies address different sources of generalization difficulty. The first focuses primarily on environmental domain shift, while the second focuses on object interaction and dense-scene detection.

This leads to the central methodology of E7 Plus:

Dual-Environment Object Composition

======================================================================

1. PROJECT OVERVIEW
   ======================================================================

Task:
Multi-class waste object detection

Classes:

* Cardboard
* Glass
* Metal
* Paper
* Plastic

Detector:
YOLO11m

Evaluation split:
Test set containing 359 images

The project investigates methods for improving waste detection under realistic environmental conditions while maintaining a controlled and reproducible evaluation protocol.

======================================================================

2. MOTIVATION
   ======================================================================

Previous experiments demonstrated that targeted augmentation (E2) produced the strongest baseline, while hard mining (E6) reduced generalization performance.

E7 Plus was designed to address a different problem: the distribution gap between the original training environment and real-world scenes.

Instead of simply increasing the number of training images, E7 Plus generates new training samples by combining reusable waste objects with realistic contexts.

However, real-world robustness is not determined only by the background. A detector may also encounter scenes containing several objects, different waste categories, overlapping instances, and partial occlusions.

Therefore, E7 Plus was designed around two complementary objectives:

1. Reduce the environmental and background domain gap.
2. Improve the detector's ability to handle complex multi-object scenes.

The resulting methodology is based on Dual-Environment Object Composition.

======================================================================

3. ARCHITECTURE
   ======================================================================

The complete pipeline follows four independent modules:

Object Bank -> Context Engine -> Dataset Builder -> YOLO Training

The architecture separates object extraction, scene generation, dataset construction, and model training so that each stage can be independently controlled and evaluated.

## 3.1 OBJECT BANK

The Object Bank is responsible for extracting reusable waste-object instances from the available training data.

Responsibilities:

* Object extraction
* Alpha mask generation
* RGBA crop creation
* Metadata storage
* Category organization

Each extracted object is represented as an RGBA crop together with metadata describing its source and class information.

This allows the same object instance to be reused in multiple environmental contexts without repeatedly extracting it from the source image.

## 3.2 CONTEXT ENGINE

The Context Engine transforms Object Bank instances into realistic scene compositions.

Its components include:

* Scaling
* Lighting adaptation
* Color temperature adjustment
* Occlusion handling
* Reflection simulation
* Object compositing

The objective is not simple copy-paste augmentation.

Instead, the Context Engine attempts to make inserted objects visually compatible with their surrounding environment by adapting properties such as scale, lighting, color temperature, and visibility relationships.

The resulting images are intended to approximate realistic scenes rather than appearing as isolated synthetic object placements.

## 3.3 DATASET BUILDER

The Dataset Builder is responsible for constructing the final training dataset from the generated samples.

It combines:

* Original training images
* Multi-object compositions
* Real-world background compositions
* Other valid synthetic training samples generated by the pipeline

The Dataset Builder also maintains the dataset split boundaries.

Validation and test images are never modified.

This separation is essential because improvements must be measured against the same evaluation distribution used by E2.

======================================================================

4. DUAL-ENVIRONMENT OBJECT COMPOSITION
   ======================================================================

E7 Plus generates additional training images through two distinct but complementary composition pipelines.

The two branches share the same Object Bank and Context Engine, but they differ in the source scene used for composition and in the learning objective.

The key distinction is:

Branch A:
Object Bank -> External Real-World Background -> Context Engine -> Synthetic Training Image

Branch B:
Existing Training Image + Object Bank Instances -> Context Engine -> Multi-Object Training Image

Both branches produce valid YOLO training samples and are subsequently merged by the Dataset Builder.

The validation and test datasets are not passed through either branch.

======================================================================

## 4.1 SHARED INPUT: OBJECT BANK

Both Branch A and Branch B begin with reusable object instances stored in the Object Bank.

Each Object Bank instance contains:

* An RGBA object crop
* An alpha mask
* A class label
* Associated metadata

The Object Bank provides the reusable waste instances that are inserted into generated scenes.

The important point is that the Object Bank is not itself a final training dataset.

It is an intermediate object repository used by the two composition branches.

======================================================================

## 4.2 SHARED PROCESSING: CONTEXT ENGINE

After an Object Bank instance is selected, it is passed through the Context Engine before being composited into the destination scene.

The Context Engine is responsible for operations such as:

* Object scaling
* Positioning
* Lighting adaptation
* Color temperature adjustment
* Occlusion handling
* Reflection simulation
* Object compositing

The purpose of this stage is to make the inserted object visually compatible with the destination scene.

Therefore, the composition process is not simply:

crop + paste

Instead, it is:

Object selection
->
Geometric adaptation
->
Appearance adaptation
->
Scene-aware compositing
->
Final synthetic image

======================================================================

# 4.3 BRANCH A - EXACT PIPELINE

Branch A is the REAL-WORLD BACKGROUND branch.

Its purpose is to change the environmental context in which a waste object appears.

The pipeline is:

Step 1:
Select an Object Bank instance.

```
    Object Bank
         |
         v
  Waste Object RGBA
```

Step 2:
Select a background from the separate real-world background dataset.

```
    Real-World Background Dataset
                 |
                 v
         Destination Scene
```

Step 3:
Adapt the selected object to the destination environment.

The Context Engine applies the required transformations, including:

* Scaling
* Position adjustment
* Lighting adaptation
* Color temperature adaptation
* Reflection handling
* Other scene-consistency operations

Step 4:
Composite the adapted object onto the real-world background.

```
    Object Bank Instance
            +
    Real-World Background
            |
            v
    Context Engine
            |
            v
    Synthetic Scene
```

Step 5:
Generate the corresponding object annotation.

The inserted object receives a bounding box and class label in the final image.

Therefore, the generated sample consists of:

Image:
Real-world background + inserted waste object

Annotation:
Bounding box + waste class

Step 6:
Send the generated sample to the Dataset Builder.

The final Branch A flow is:

Object Bank
->
Select waste object
->
Select external real-world background
->
Scale / position object
->
Adapt lighting and appearance
->
Composite object into background
->
Generate bounding box + class annotation
->
Branch A training sample
->
Dataset Builder

## BRANCH A LEARNING TARGET

Branch A primarily changes the environmental context.

The object identity remains the same, while the surrounding environment changes.

Conceptually:

Same object
+
Different real-world environments
=================================

Environmental diversity

Therefore, Branch A is intended to reduce dependence on the original background distribution and expose the detector to a broader range of realistic environmental conditions.

======================================================================

# 4.4 BRANCH B - EXACT PIPELINE

Branch B is the MULTI-OBJECT COMPOSITION branch.

Its purpose is different from Branch A.

Instead of starting from an external background, Branch B starts from an existing training image.

The pipeline is:

Step 1:
Select an existing training image.

```
    Original Training Image
              |
              v
      Existing Scene
```

Step 2:
Read the objects and annotations already present in that image.

For example:

Original scene:

```
    [Glass]
```

The original bounding box and class label are retained.

Step 3:
Select one or more additional Object Bank instances.

```
    Object Bank
         |
         +---- Plastic
         |
         +---- Metal
         |
         +---- Paper
```

Step 4:
Select placement locations for the additional objects inside the existing scene.

The new objects are positioned relative to the existing scene rather than being placed onto a completely new background.

The placement can create:

* Nearby instances
* Multiple objects
* Multiple classes
* Overlap
* Partial occlusion

Step 5:
Pass the additional objects through the Context Engine.

The Context Engine adapts:

* Scale
* Position
* Lighting
* Color temperature
* Reflection
* Occlusion relationship
* Composite appearance

Step 6:
Composite the additional Object Bank instances into the original training image.

For example:

Before:

```
    [Glass]
```

After:

```
    [Glass]       [Plastic]

           [Metal]
```

The original Glass object remains in the image.

The newly inserted Plastic and Metal objects are added to the same scene.

Step 7:
Update the annotations.

This is a critical difference from simple image augmentation.

The final image must contain valid annotations for:

1. The original objects already present in the source image.
2. The newly inserted Object Bank instances.

Therefore, if the original image contains:

Glass

and two additional objects are inserted:

Plastic
Metal

the final annotation set contains:

Glass bounding box
Plastic bounding box
Metal bounding box

Step 8:
Send the generated multi-object image to the Dataset Builder.

The final Branch B flow is:

Original Training Image
->
Preserve original objects and annotations
->
Select additional Object Bank instances
->
Determine new object placements
->
Scale / position objects
->
Adapt lighting and appearance
->
Create overlap / occlusion when applicable
->
Composite new objects
->
Merge original + new annotations
->
Branch B training sample
->
Dataset Builder

## BRANCH B LEARNING TARGET

Branch B primarily changes the structure of the scene rather than replacing its environment.

Conceptually:

Existing training scene
+
Additional waste instances
==========================

Multi-object scene

This exposes YOLO11m to situations where multiple valid objects and classes coexist within the same image.

The intended learning effects include:

* Multi-object detection
* Multi-class localization
* Instance separation
* Overlap handling
* Occlusion robustness
* Dense-scene understanding

======================================================================

# 4.5 THE CRITICAL DIFFERENCE BETWEEN BRANCH A AND B

The two branches should not be described as two versions of the same augmentation.

They start from different scene sources.

Branch A starts from:

External real-world background

Branch B starts from:

Existing training image

Branch A changes:

WHERE the object appears.

Branch B changes:

WHAT ELSE appears around the object.

Branch A:

Object Bank
+
New real-world environment
->
Environmental domain adaptation

Branch B:

Existing training image
+
Additional Object Bank instances
->
Multi-object scene complexity

This distinction is the central design principle of E7 Plus.

# 4.7 ANNOTATION FLOW

Annotation handling is different in the two branches.

Branch A:

External background
+
Inserted object
===============

New annotation for inserted object

Branch B:

Original training image
+
Original annotations
+
Inserted objects
================

Original annotations
+
New annotations

This means Branch B must preserve the annotation information of the original image while adding annotations for every newly inserted valid object.

The resulting image therefore remains a valid multi-object detection training sample.

======================================================================

# 4.8 DATASET BUILDER

After generation, Branch A and Branch B do not directly train the detector.

Both branches first pass their generated samples to the Dataset Builder.

The Dataset Builder combines:

Original Training Images
+
Branch A Generated Samples
+
Branch B Generated Samples
==========================

Final E7 Plus Training Dataset

The Dataset Builder is therefore the point at which the two independent generation strategies become a single training distribution.

The final training dataset contains:

1. Original real training images.
2. Synthetic images with real-world background composition.
3. Synthetic multi-object images based on existing training images.

======================================================================

# 4.10 WHAT E7 PLUS ACTUALLY CHANGES

E7 Plus modifies the training distribution along two independent dimensions.

Dimension 1:
Environmental Context

Handled by Branch A.

The same waste categories are exposed to different real-world environments.

Dimension 2:
Scene Composition

Handled by Branch B.

The detector is exposed to multiple waste instances, multiple classes, overlap, and partial occlusion within a single scene.

Therefore:

# E7 Plus

Environmental Diversity
+
Scene Complexity

======================================================================

# 4.11 WHAT E7 PLUS DOES NOT DO

E7 Plus does not:

* Replace the original training dataset completely.
* Generate synthetic validation images.
* Generate synthetic test images.
* Modify test annotations.
* Use the test set as a composition source.
* Treat Branch A and Branch B as identical augmentation operations.

The original training distribution remains part of the final training dataset.

The validation and test distributions remain unchanged.

======================================================================

# 4.12 FINAL METHODOLOGICAL DEFINITION

The most precise description of the E7 Plus pipeline is:

"E7 Plus is a dual-branch, object-centric training-data expansion pipeline. Branch A composes reusable waste-object instances from the Object Bank into external real-world backgrounds to increase environmental diversity and reduce background domain gap. Branch B inserts additional Object Bank instances into existing training images to construct multi-object scenes containing multiple classes, object overlap, and partial occlusion. The generated samples from both branches are merged with the original training images by the Dataset Builder, while validation and test datasets remain unchanged."

In short:

Branch A changes the ENVIRONMENT.

Branch B changes the SCENE COMPOSITION.

Together they expand the training distribution without changing the evaluation distribution.

10. ENGINEERING DECISIONS
    ======================================================================

Several engineering principles were maintained throughout E7 Plus:

* Modular architecture
* Separation of object extraction, scene generation, dataset construction, and training
* Dual-environment composition strategy
* Separation of augmentation from model training
* No modification of validation or test data
* Runtime-independent deployment benchmarking
* Data-driven visualization pipeline
* Reproducible evaluation outputs
* Reusable Object Bank representation
* Configurable Context Engine components

The modular design also makes it possible to independently modify future composition strategies without redesigning the complete training pipeline.

13. METHODOLOGICAL INTERPRETATION
    ======================================================================

E7 Plus can be interpreted as a two-axis training-distribution expansion strategy.

The first axis concerns the environment:

Where does the waste object appear?

Branch A expands this dimension by introducing real-world backgrounds and environmental contexts.

The second axis concerns the scene structure:

What other objects are present, and how do they interact?

Branch B expands this dimension by creating multi-object scenes with multiple classes, overlap, and partial occlusion.

Therefore, E7 Plus does not treat domain adaptation simply as background replacement.

Instead, it modifies the training distribution at both the environmental level and the object-interaction level.

This distinction is central to the methodology of E7 Plus.

14. CONCLUSION
    ======================================================================

E7 Plus improves the Smart Waste Detection system through a modular synthetic data generation pipeline while preserving a controlled evaluation protocol.

The main methodological contribution is the combination of two complementary composition strategies:

1. Real-world background composition for environmental domain adaptation.

2. Multi-object composition for learning complex scenes, object interactions, overlap, and occlusion.

The resulting training distribution is therefore richer in both environmental diversity and scene complexity, while validation and test remain completely unchanged.

On the fixed test set, E7 Plus achieves:

mAP@0.50:
0.9569

mAP@0.75:
0.9536

mAP@0.50:0.95:
0.8765

The primary remaining limitation is the visual similarity between Glass and Metal, which produces reciprocal classification confusion and represents an important direction for future investigation.

Overall, E7 Plus demonstrates a modular approach in which Object Bank, Context Engine, and Dataset Builder work together to expand the training distribution along complementary dimensions rather than merely increasing the number of training samples.

The central idea of E7 Plus can therefore be summarized as:

Object Bank
->
Reusable waste instances

Context Engine
->
Realistic environmental and object interactions

Dual-Environment Composition
->

1. Real-world background adaptation
2. Multi-object and occlusion augmentation

Dataset Builder
->
Expanded training distribution

YOLO11m
->
Detection model evaluated on the unchanged test distribution

This architecture provides a reproducible framework for studying how synthetic data generation can improve real-world object detection without contaminating the evaluation protocol.
